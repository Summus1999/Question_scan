# PRD：Question Scan 桌面算法解题助手

## 1. 概述

Question Scan 是一个基于 Tauri 的桌面软件。用户按下全局快捷键后，软件截取当前屏幕，自动识别屏幕中的算法题区域，生成临时图片，并把图片和用户配置发送给多模态 AI。AI 返回题目分析、解题思路、主流语言代码、复杂度说明和边界条件。产品默认用于授权练习、自测、开放题目环境和个人效率场景。

这个产品的核心不是导师式教学，而是快速把屏幕上的算法题转换成可用答案。用户可以配置默认语言、输出速度、模型服务、结果格式和是否保存历史。

MVP 之后，Question Scan 会增加三个可选增强方向：本地 RAG 知识增强、多层容错 Agent 工作流和远端 Provider Proxy。RAG 用于召回用户自己的题解、错题、代码模板、历史题目和轻量题目索引。Agent 用于把截图、裁剪、识别、检索、生成、解析和展示串成可见的容错流程。远端 Provider Proxy 用于托管 API Key、统一转发模型请求和做备用服务切换。三个方向都必须保持用户主动触发、用户可控、数据流透明，不改变产品的授权练习、自测、开放题目环境和个人工作流边界。

## 2. 产品目标

- 用户按下快捷键后，5 秒内完成屏幕截图和题目区域识别。
- 用户无需复制题目文本，也能从截图得到结构化题目内容。
- 用户可以选择 C++、Python、Java、JavaScript、TypeScript、Go、Rust 等主流语言生成答案。
- 用户可以配置结果面板的流式展示速度。真实生成速度由模型和网络决定，软件控制本地展示节奏。
- 用户可以把 AI 输出复制到剪贴板，保存到本地历史，或导出为代码文件。
- 软件只在用户主动触发时截图，并在请求完成后删除临时图片，除非用户选择保存历史。
- 后续版本中，用户可以开启本地知识增强，从自己的历史题目、错题笔记、代码模板和轻量题目索引中召回相似上下文。
- 后续版本中，软件可以用可见的 Agent 工作流处理截图、裁剪、识别、RAG、AI 请求和输出解析中的失败，并向用户展示降级路径。
- 后续版本中，用户可以选择本地直连模型服务，或使用自己配置的远端 Provider Proxy 托管 API Key 和转发请求。

## 3. 目标用户

- 正在准备算法笔试、机试和技术面试的开发者。
- 希望减少刷题检索、复制、整理时间的用户。
- 在开放练习环境中需要快速生成参考解法的人。
- 需要对同一道题生成多语言答案的人。
- 希望把自己的题解、错题、模板和历史记录沉淀为本地检索资料的人。

## 4. 核心用户流程

1. 用户打开软件，配置 AI Provider、API Key、默认模型、默认语言和输出速度。
2. 用户在浏览器、PDF、IDE 或题库页面中看到一道算法题。
3. 用户按下全局快捷键，例如 `Ctrl+Shift+Q`。
4. 软件截取所有显示器的当前画面。
5. 软件识别最可能的算法题区域，并生成裁剪后的临时图片。
6. 软件把临时图片、默认语言和输出格式要求发送给 AI。
7. AI 返回题目文本、解题思路、代码、复杂度和边界条件。
8. 软件在结果面板中按配置速度展示内容。
9. 用户复制代码、保存记录，或切换语言重新生成。

可选增强流程：

1. 用户在设置中开启本地知识增强，并导入自己的题解、错题笔记或代码模板。
2. 用户触发截图后，软件识别题目文本，并在本地检索相似题、算法标签、历史记录和可用模板。
3. 软件把高置信度的本地上下文压缩后加入解题请求，并在结果面板中显示本次使用的上下文来源。
4. 如果截图、裁剪、识别、RAG 或 AI 请求失败，Agent 工作流显示当前步骤、失败原因、重试次数和降级路径。
5. 如果用户启用远端 Provider Proxy，软件把裁剪图、识别文本和请求参数发送到用户配置的代理服务，再由代理服务转发给模型服务。

## 5. 功能需求

### 5.1 全局快捷键

FR-001：系统必须支持用户配置全局快捷键。

FR-002：系统必须在后台运行时响应快捷键。

FR-003：系统必须支持启用、禁用和重置快捷键。

FR-004：当快捷键和系统或其他应用冲突时，系统必须提示用户重新设置。

### 5.2 屏幕截图

FR-005：系统必须支持截取当前屏幕。

FR-006：系统必须支持多显示器截图。

FR-007：系统必须在截图前显示状态反馈，例如托盘图标变化或面板状态变化。

FR-008：系统必须在本地生成临时图片文件。

FR-009：系统必须在请求完成后删除临时图片，除非用户启用保存截图。

### 5.3 题目区域识别

FR-010：系统必须从全屏截图中定位最可能的算法题区域。

FR-011：系统必须支持题目区域自动裁剪。

FR-012：系统必须支持识别失败后的手动框选兜底方案。

FR-013：系统必须识别题目中的标题、描述、输入输出、示例、约束和函数签名。

FR-014：系统应支持中文题目和英文题目。

### 5.4 AI 请求与答案生成

FR-015：系统必须支持 OpenAI-compatible 的多模态模型接口。

FR-016：系统必须允许用户配置 API Base URL、API Key、模型名和请求超时时间。

FR-017：系统必须把裁剪后的临时图片作为主要输入发送给 AI。

FR-018：系统必须把默认语言、答案风格、输出格式和用户偏好一起发送给 AI。

FR-019：系统必须支持流式输出。

FR-020：系统必须在 AI 请求失败时展示明确错误信息，并允许重试。

### 5.5 直接解题输出

FR-021：系统必须输出可复制的完整代码。

FR-022：系统必须输出题目识别结果，便于用户确认 AI 是否看懂题目。

FR-023：系统必须输出核心算法思路，但不以教学对话为主要形态。

FR-024：系统必须输出时间复杂度和空间复杂度。

FR-025：系统必须输出边界条件和常见测试用例。

FR-026：系统必须支持一键切换语言并重新生成答案。

FR-027：系统必须支持 C++17 或 C++20 作为默认语言选项。

### 5.6 输出速度配置

FR-028：系统必须支持配置结果面板的展示速度。

FR-029：展示速度配置至少包含三档：快速、正常、慢速。

FR-030：系统应支持自定义字符每秒或代码块逐段展示。

FR-031：系统必须说明展示速度不等于模型生成速度。模型生成速度受 Provider、模型、网络和请求负载影响。

### 5.7 结果面板

FR-032：系统必须提供一个可固定、可收起的结果面板。

FR-033：结果面板必须展示请求状态：截图中、识别中、生成中、完成、失败。

FR-034：结果面板必须支持复制完整代码。

FR-035：结果面板必须支持复制完整答案。

FR-036：结果面板必须支持清空当前结果。

FR-037：结果面板应支持 Markdown 和代码高亮。

### 5.8 语言与模板

FR-038：系统必须支持配置默认编程语言。

FR-039：系统必须支持 C++、Python、Java、JavaScript、TypeScript、Go 和 Rust。

FR-040：系统应支持按语言配置代码风格，例如 C++ 使用 `#include <bits/stdc++.h>` 或标准头文件。

FR-041：系统应支持题目平台模板，例如 ACM 输入输出、LeetCode 函数签名、牛客输入输出。

### 5.9 本地历史

FR-042：系统应支持保存历史记录。

FR-043：历史记录应包含截图时间、题目识别文本、语言、AI 输出、用户备注和模型信息。

FR-044：系统必须允许用户关闭历史保存。

FR-045：系统必须允许用户删除单条历史和清空全部历史。

### 5.10 隐私与数据控制

FR-046：系统必须只在用户主动触发快捷键时截图。

FR-047：系统必须提示用户截图会发送给所配置的 AI 服务。

FR-048：系统必须避免默认保存完整屏幕截图。

FR-049：系统必须允许用户查看和删除本地缓存。

FR-050：系统必须在设置页展示数据流向：屏幕截图、本地裁剪、临时图片、AI 请求、结果保存。

### 5.11 本地 RAG 与题目上下文增强

FR-051：系统应支持可选的本地知识增强开关，默认关闭。

FR-052：系统应支持 LeetCode 轻量题目索引，索引内容只包含题号、标题、slug、难度、标签、题型和平台来源，不默认内置未授权完整题面。

FR-053：系统应允许用户导入自己的 Markdown、JSON 或 CSV 题解、错题笔记和代码模板。

FR-054：系统应为导入资料记录来源、导入时间、更新时间和删除入口。

FR-055：当用户开启历史保存和历史入库时，系统应把识别出的题目文本、AI 输出摘要、用户备注、语言和标签保存为可检索记录。

FR-056：系统应支持为题目文本、用户笔记、代码模板和历史记录生成 embedding，并保存到本地索引。

FR-057：系统应支持按题干、标题、样例、约束、标签和语言召回 top K 相似题、相关笔记和代码模板。

FR-058：系统必须限制 RAG 召回条数和上下文 token 预算，避免低置信度内容覆盖截图识别结果。

FR-059：系统必须在解题请求中区分截图识别内容和本地召回内容，并提示模型优先相信当前截图和用户确认内容。

FR-060：结果面板应展示本次命中的相似题、本地模板、历史记录、来源和置信度。

FR-061：用户必须可以关闭历史入库、清除 RAG 索引、删除单条导入资料和重建索引。

FR-062：当本地索引为空、embedding 失败或召回置信度过低时，系统必须跳过 RAG 增强，并继续原有解题流程。

### 5.12 多层容错 Agent 工作流

FR-063：系统应提供可选的智能容错工作流，用于编排截图、裁剪、识别、检索、生成、解析、展示和保存步骤。

FR-064：Agent 工作流必须向用户展示当前步骤状态，包括截图中、裁剪中、识别中、检索中、生成中、解析中、完成和失败。

FR-065：Agent 工作流必须记录每个步骤的输入摘要、输出摘要、成功条件、失败原因、重试次数和降级路径。

FR-066：截图阶段失败时，系统必须提示多显示器枚举失败、权限不足、截图为空、图片过大或临时文件写入失败等具体原因。

FR-067：裁剪阶段失败或自动定位低置信度时，系统必须进入手动框选兜底，并保留重新自动识别入口。

FR-068：识别阶段失败时，系统应支持本地 OCR 或手动确认题目标题和题干作为兜底输入。

FR-069：RAG 阶段失败时，系统必须跳过增强，不阻塞截图到解题的主流程。

FR-070：AI 请求阶段出现超时、限流、网络错误或服务端错误时，系统应按用户配置重试、降级到非流式响应或切换备用 provider。

FR-071：备用 provider 只能使用用户明确配置过的服务，系统不得自动把请求发送到未配置服务。

FR-072：输出解析失败时，系统应先本地提取主代码块，再可选请求一次格式修复；仍失败时展示原始输出并标记复制限制。

FR-073：用户应能配置最大重试次数、是否启用备用 provider、是否启用 OCR 兜底和是否展示详细步骤日志。

FR-074：Agent 工作流不得新增隐蔽截图、窗口隐藏、监控规避、自动提交或自动填答案能力。

### 5.13 远端 Provider Proxy 与 API Key 托管

FR-075：系统应支持本地直连和远端 Provider Proxy 两种 provider 模式。

FR-076：远端 Provider Proxy 必须默认关闭，只有用户主动配置代理地址和用户 token 后才启用。

FR-077：系统必须在设置页说明远端代理模式的数据流：裁剪图、识别文本、prompt、模型参数会发送到用户配置的代理服务。

FR-078：系统必须允许用户随时关闭远端代理，并回到本地 API Key 直连模式。

FR-079：代理 token 必须按密钥存储策略保存，不得写入普通设置文件。

FR-080：系统应支持代理连接测试、鉴权失败提示、超时提示、限流提示和服务端错误提示。

FR-081：远端代理请求协议应支持流式输出、非流式输出、错误标准化、超时、限流、备用 provider 和审计元数据。

FR-082：代理不可用时，系统应按用户配置提示重试、切回本地 provider 或终止请求。

FR-083：远端代理默认不得保存截图、题面和完整回答日志。如用户或部署方开启日志，日志范围应限制为时间、模型、错误码、耗时和用量估算。

FR-084：系统必须在隐私文档中说明远端代理模式的责任边界、数据流、日志策略和关闭方式。

## 6. 非目标范围

- 不做隐蔽用于真实面试、在线考试或受限评估的功能。
- 不做检测规避、屏幕共享规避、窗口隐藏规避或反监控能力。
- 不做自动提交到第三方题库平台。
- 不做自动填入第三方网页答案框。
- 不读取用户账号、Cookie、浏览器私密数据或第三方平台凭据。
- 不默认内置或分发未授权的完整 LeetCode 题面。
- 不自动抓取第三方题库内容作为本地知识库。
- 不把 RAG 命中结果当成当前截图题目的唯一事实来源。
- 不通过远端代理绕过用户本地的数据流确认。
- 不在远端代理中默认保存截图、题面、prompt 或完整回答。
- MVP 不做云同步、账号系统、支付系统和团队管理。
- MVP 不做完整本地判题系统。

## 7. 设计要求

- 主界面应以结果面板和设置为核心，不做复杂学习路径。
- 软件启动后进入托盘和简洁控制台。
- 状态反馈要清楚，用户能知道当前处于截图、识别、请求还是输出阶段。
- 代码区域要支持语法高亮、复制和折叠。
- 设置项要集中：快捷键、AI Provider、语言、输出速度、历史保存、隐私选项。
- 出错时要给出可执行建议，例如检查 API Key、模型是否支持图片、网络是否可用。
- 本地知识增强必须在设置页中独立展示，包含启用状态、资料来源、索引大小、清除入口和数据流说明。
- Agent 工作流状态必须出现在结果面板中，用户能看到当前步骤、失败原因和是否触发降级。
- 远端代理模式必须用清晰文案说明哪些数据会离开本机，并提供连接测试和关闭入口。

## 8. 技术方案建议

### 8.1 桌面框架

- Tauri 2.x
- Rust 后端
- React + TypeScript + Vite 前端
- Tailwind CSS
- shadcn/ui 或 Radix UI
- lucide-react 图标

### 8.2 Tauri 能力

- 使用全局快捷键插件监听用户触发。
- 使用 Rust 截图库捕获当前屏幕。
- 使用 `image` 类库完成裁剪、压缩和临时文件生成。
- 使用 Rust 后端发起 AI 请求，减少 API Key 暴露。
- 使用系统托盘承载后台运行状态。

### 8.3 题目定位方案

MVP 推荐两级方案：

- 自动方案：把全屏截图低清压缩后交给视觉模型，要求返回题目区域坐标和题目文本，再本地裁剪高清区域。
- 兜底方案：自动识别失败时，让用户手动框选题目区域。

后续版本可以加入本地 OCR，提高定位速度，减少 AI 调用成本。

### 8.4 AI Prompt 输出结构

AI 输出必须固定为以下结构：

```text
题目识别：
解题策略：
代码语言：
完整代码：
复杂度：
边界用例：
注意事项：
```

代码输出必须优先满足用户选择的语言和平台模板。

### 8.5 本地存储

- SQLite 保存设置和历史。
- 系统临时目录保存请求过程中的图片。
- 默认不保存完整截图。
- 用户开启历史时保存题目文本和答案。

### 8.6 本地 RAG 建议

- 使用 SQLite 保存题目索引、用户资料、历史记录、分块结果、embedding 元数据和召回记录。
- LeetCode 轻量索引只保存题号、标题、slug、难度、标签、题型和平台来源。
- 用户导入资料支持 Markdown、JSON 和 CSV，导入后按标题、题干、标签、代码模板和备注分块。
- embedding 可先支持 OpenAI-compatible embedding 服务或本地 embedding Provider，具体 Provider 由用户配置。
- RAG 上下文注入前必须做长度裁剪、来源标记和置信度过滤。
- 历史入库和用户资料检索必须能单独关闭。

### 8.7 Agent 工作流建议

- 后端可以增加 Agent 状态机模块，把 `capture`、`crop`、`recognize`、`retrieve`、`solve`、`parse`、`render` 和 `save` 定义为明确步骤。
- 每个步骤应有统一的输入、输出、错误类型、重试策略和降级路径。
- 前端通过事件订阅步骤状态，结果面板展示状态进度和失败原因。
- OCR 兜底应作为可选能力接入，不能阻塞手动框选主链路。
- Agent 工作流只做用户可见的本地编排，不做隐蔽触发、窗口隐藏或第三方网页自动操作。

### 8.8 远端 Provider Proxy 建议

- Provider 层保留本地直连路径，并新增可选代理路径。
- 代理请求协议应兼容现有 OpenAI-compatible 请求结构，并统一错误映射。
- 桌面端只保存代理地址和用户 token；真实 provider key 由代理服务托管。
- 代理服务默认不保存截图、题面、prompt 和完整回答。
- 如果提供最小代理服务样例，应只用于开发验证 token 鉴权、请求转发、流式响应和错误映射。

## 9. 开发阶段规划

## 10. MVP 验收标准

以下标准只用于第一版 MVP。RAG、Agent 工作流和远端 Provider Proxy 属于 MVP 后增强能力，不阻塞第一版 MVP 验收。

- 用户可以配置 API Key、模型、语言和快捷键。
- 用户按下快捷键后，软件可以截取屏幕并生成临时图片。
- 软件可以识别屏幕中的算法题区域，识别失败时允许手动框选。
- 软件可以把临时图片发送给 AI 并获得结构化答案。
- 用户可以选择 C++ 并得到可复制的完整代码。
- 用户可以配置结果展示速度。
- 软件默认不保存完整截图。
- 软件重启后保留用户设置。

## 11. 后续增强验收标准

### 11.1 本地 RAG 验收标准

- 用户可以开启或关闭本地知识增强。
- 用户可以导入自己的题解、错题笔记和代码模板。
- 软件可以从本地索引召回相似题、题型标签、历史记录和代码模板。
- 解题请求中能注入压缩后的高置信本地上下文。
- 结果面板能展示本次使用的上下文来源。
- 用户可以清除 RAG 索引、删除导入资料和关闭历史入库。

### 11.2 Agent 工作流验收标准

- 结果面板能显示截图、裁剪、识别、检索、生成、解析和展示步骤。
- 自动裁剪低置信度时能进入手动框选。
- RAG 失败时不阻塞主解题流程。
- AI 请求临时失败时能按配置重试或切换备用 provider。
- 输出格式异常时能提取主代码块或展示原始输出。
- 每条失败路径都有用户能理解的错误提示和下一步动作。

### 11.3 远端 Provider Proxy 验收标准

- 用户可以在本地直连和远端代理之间切换。
- 用户可以配置代理地址和用户 token，并做连接测试。
- 代理模式下能完成流式和非流式请求。
- 代理鉴权失败、超时、限流和服务端错误都有明确提示。
- 关闭代理后，请求回到本地直连模式。
- 隐私文档说明代理模式的数据流和日志策略。

## 12. 风险和应对

- 风险：全屏截图包含隐私信息。应对：只在用户主动触发时截图，默认不保存完整截图，设置页展示数据流向。
- 风险：题目区域识别不准。应对：先做手动框选兜底，再优化自动定位。
- 风险：不同 AI 模型对图片理解能力差异大。应对：设置页标注模型要求，错误信息提示模型需要支持图片输入。
- 风险：生成代码不能通过所有用例。应对：输出边界用例，并在后续版本加入本地样例运行。
- 风险：跨平台截图权限不同。应对：MVP 先以 Windows 为主，后续扩展 macOS 和 Linux。
- 风险：RAG 召回了错误相似题，导致答案被带偏。应对：显示召回来源和置信度，限制上下文预算，并提示模型优先相信当前截图和用户确认内容。
- 风险：用户导入资料包含敏感内容。应对：RAG 默认本地运行，提供删除、清空索引和关闭历史入库入口。
- 风险：LeetCode 题面版权边界不清。应对：只内置轻量索引，不默认分发完整题面，完整内容来自用户截图、用户导入或用户历史。
- 风险：Agent 自动降级让用户误解当前结果可靠性。应对：展示步骤日志、失败原因、重试次数和最终使用的 provider。
- 风险：远端代理增加数据外发面。应对：代理默认关闭，设置页展示数据流，隐私文档说明日志策略，用户可以随时切回本地直连。
